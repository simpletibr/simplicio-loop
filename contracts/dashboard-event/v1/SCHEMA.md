# `simplicio.dashboard-event/v1`

One JSON object per line in `<run-dir>/events.jsonl`. Every envelope carries all of these fields
and no others, except the optional `derived: true` on events rebuilt from older runs:

| Field | Rule |
|---|---|
| `schema` | `simplicio.dashboard-event/v1` |
| `event_id` | ULID |
| `seq` | integer ≥ 1, monotonic and gap-free per run |
| `ts` | UTC, `YYYY-MM-DDTHH:MM:SS.mmmZ` |
| `run_id` | non-empty string |
| `task_id` | string, or `null` for `scope: collection` |
| `scope` | `collection` (task_id null), `task` or `scenario` (task_id required), as in `simplicio.event-metadata/v1` |
| `source` | `hook`, `runner`, `worker`, `oracle` or `operator` |
| `kind` | a loop catalog name, or `<namespace>.<kind>` for another product (`loop.` is reserved) |
| `phase`, `lane` | string or `null` |
| `iteration` | integer ≥ 0 or `null` |
| `severity` | `debug`, `info`, `warning` or `error` |
| `payload` | object |
| `refs` | array of non-empty strings (receipts/files; relative to the run directory when inside it) |
| `producer_version` | `<producer>@<version>` |

Compatibility: adding a loop kind or a payload field is backward compatible; renaming or removing
an envelope field, a kind, or changing a type needs `dashboard-event/v2`.

The fixtures in `fixtures/` are produced by the real runner, hooks and retroactive adapter and are
re-generated by `scripts/check_dashboard_event_contract.py` on every `scripts/check.py` run;
`fixtures/invalid.jsonl` lists envelopes that must be rejected. Kind table, producers, sink
behaviour and examples: `docs/DASHBOARD_EVENTS.md`.
