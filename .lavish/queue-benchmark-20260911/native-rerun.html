What was actually exercised

  • run, automatic batch, batch --serial, widths 10 and 30, and tick.
  • GitHub tasks run release preflight and checkout dry-run; the latter read all ten issues and produced a plan only.
  • Prism arm, Mapper queue status/top/doctor, legacy queue status/doctor, drain evaluate/persist/load, single-task-fast, hub-drain-plan/admit, and Fast on/off preflight.
  • Central Mapper preparation took 9.669 s for ten task records; snapshot build took 0.350 s. The integrated Fast path rejected the current handoff/artifact layout, so it was not ranked.
  • 107 help invocations were reconciled separately; help coverage is not workflow completion.

Standard to retest

Central Mapper preparation → bounded Fast context → Runtime capacity admission → automatic Prism batch with machine-recommended workers/wave → reconcile → independent verify.

Use --serial only for a diagnostic or when Prism is ineligible. Keep physical backpressure enabled; do not override the governor to manufacture a winner.
