# Issue #1328 — wave evidence

Three loop defects found while delivering #1323 through the wave, fixed and
proven end to end.

## Root causes and fixes

1. **False-positive `plan_repo_state_stale` after the run's own mutation.**
   `_execute_operator_unleased` (`simplicio_loop/runner.py`) advanced
   `state["repo_state_chain"]` only when the operator returned 0. An
   "uncertain" outcome (client-side timeout after the operator had already
   written) left the chain at the `prepare`-time fingerprint, so the next
   dependent task's freshness check saw the run's own edit as external drift
   and dead-lettered the run. The chain now re-binds on `returncode == 0 or
   uncertain`; a genuine external edit between `prepare` and dispatch is still
   caught by the pre-attempt freshness check (regression test kept).
2. **Plain `orient` left no Mapper project map**, so `prepare` failed closed
   with `mapper_fast_provenance_missing` on a fresh repo. `orient` and
   `orient --brief` now call `_ensure_project_map()` (`simplicio_loop/cli_impl.py`),
   which runs `simplicio-mapper index` once when
   `.simplicio-loop/project-map.json` is missing. The survey gate itself stays
   fail-closed.
3. **`.claude/` targets rejected.** `_extract_repo_file_hints` excluded every
   `.claude/` path. Skill files named explicitly by the task
   (`.claude/skills/**`, `plugin/skills/**`, `simplicio_loop/_bundle/skills/**`)
   are now authorized targets; other `.claude/` internals stay excluded.

## Dogfood on this repository

The SKILL.md clarification in this change (wave edit plans are find/replace
only; creating files is `apply` today, #1331) was applied by the real
operator in `run-20260926-102026-y7i3204e`: `prepare` accepted the
`.claude/skills/simplicio-loop/SKILL.md` target (fix 3) and
`simplicio-dev-cli edit --apply` wrote the byte-identical text. That run did
not reach a clean `verify`, for two reasons outside #1328's defects:

- `orient`'s best-effort `simplicio-mapper index` has a 60 s timeout; on this
  ~3,900-file monorepo the index took ~280 s, so it was run once by hand.
- `simplicio-dev-cli edit --apply` runs the repository's whole `pytest -q`
  as its own verification (15+ min here). An outer `timeout 300` killed the
  wave mid-verify, and the retries failed closed on that interruption
  (`stale mapper context`, `SLOT_CAPACITY`), as designed.

Both are tracked in #1331 (full Mapper re-index per call; unbounded dev-cli
verification).
