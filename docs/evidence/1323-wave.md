### Task 3 (Docs, SKILL.md) — applied by hand, documented reason

`prepare` cannot express an edit whose only candidate target lives under
`.claude/`: `simplicio_loop/runner.py`'s `_extract_repo_file_hints` (used
both for a task's explicit file hints and, via `_task_context_plan_data`'s
context-pack filter, for candidate-target derivation) hard-excludes any path
starting with `.claude/` (`runner.py:4536`, `:4620`, `:4805` — the same
guard that keeps `.claude/` out of the mapper-freshness fingerprint,
`_is_loop_owned_status_path`, `runner.py:2273`). Reproduced directly:

```
$ python3 -c "
from pathlib import Path
from simplicio_loop.runner import _extract_repo_file_hints
print(_extract_repo_file_hints(open('tasks-full.md').read().split('System: simplicio_loop')[3], Path('.').resolve()))
"
[]
```

With zero candidate targets, `plan_contract.validate_plan` raises
`task[n] targets_missing`, which `runner.py` maps to
`RuntimeError("mapper-derived plan has no authorized operator target")` —
`prepare` blocks with `reason_code: no_authorized_target` before any
operator ever runs, for every attempt (confirmed twice, with all 3 tasks
armed together and with the SKILL.md task isolated). This is a genuine,
structural inability of the wave's automatic target-derivation path to
target `.claude/skills/**` files, not a plan/tasks.md authoring mistake — so
per the run instructions this one line was applied directly:

```diff
 - **Effort:** plan **high** → execute **low** → review **medium**. Use the `effort` of each `route.next` step and the `next_effort` of `apply`'s result.
+- `apply` PASS means every `check` already ran — you are done; do not re-open the receipt or re-run checks.
 - No `tasks.md`, no run, no scratchpad, no progress header on this path.
```

## Loop findings (bugs / gaps noticed, not fixed here — out of this issue's scope)

1. **`orient --task` (non-`--brief`) does not itself produce
   `.simplicio-loop/project-map.json`.** `survey.provenance()` requires that
   file to exist (it is the Mapper-generation identity `apply`/`prepare`
   check for). On a fresh worktree, `orient --task` alone left
   `prepare` BLOCKED on `mapper_fast_provenance_missing` even though
   `orient` had just run and written `survey.json`. Running
   `simplicio-mapper index <repo> --json` once directly (the same binary
   `orient` shells out to) produced `project-map.json` and unblocked
   `prepare`. Worth a follow-up: either `orient --task` should ensure
   `project-map.json` exists (call the same `index` step `--brief` already
   relies on via `map_service_mapper.py`), or `survey.provenance()`'s error
   message should name the missing file explicitly instead of the generic
   Mapper+Fast hint.
2. **`wave`'s post-apply plan-freshness re-check produces a false-positive
   `plan_repo_state_stale` even on a successful, single-task run.** In both
   runs above, the operator's `simplicio-dev-cli` mutation landed correctly
   (verified via `git diff` matching the supplied edit-plan) before a
   subsequent validation pass rejected the SAME task (or the next one) for a
   tree that moved only because of that same wave's own just-applied
   mutation. The run is left `BLOCKED`/dead-lettered despite the source edit
   being exactly right. This looks like the dispatcher not refreshing its
   frozen `plan.repo_state` baseline immediately after a task's own
   successful mutation before the next validation/retry pass reads it. A
   proper fix belongs in `simplicio_loop/runner.py`'s wave dispatch/retry
   path and is a bigger, riskier change than this issue's scope — flagged
   as a follow-up rather than patched blind under this delivery.
3. Task text must literally name a real, existing repo-relative path (not a
   nonexistent file used only inside a Gherkin `Given` clause for a unit
   test's own `tmp_path` fixture) or `validate_plan` fails closed with
   `target_missing_without_to_create`. The first `tasks-wave.md` draft named
   `tests/test_a.py`/`tests/test_big.py` (the throwaway fixture paths used
   *inside* the unit test) and had to be reworded to reference the real
   `tests/test_orient_brief_unit.py` instead.
