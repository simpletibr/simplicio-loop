# Dashboard events — `simplicio.dashboard-event/v1`

One append-only event stream per run that the live dashboard (epic #1397) consumes in real time,
instead of polling `state.json`, `transitions.jsonl` and dozens of receipts. Issue #1398 defines it;
the dashboard backend (#1400) and the marketing dashboard (`simplicio-loop-marketing#172`) read it.

- Contract: [`contracts/dashboard-event/v1/schema.json`](../contracts/dashboard-event/v1/schema.json)
  (authoritative) and [`SCHEMA.md`](../contracts/dashboard-event/v1/SCHEMA.md).
- Fixtures generated by the real producers: `contracts/dashboard-event/v1/fixtures/`.
- Emitter (stdlib only): `scripts/dashboard_events.py`; package seam: `simplicio_loop/dashboard_events.py`.
- Drift gate: `python3 scripts/check_dashboard_event_contract.py` (a phase of `scripts/check.py`).

## Sink

`<run-dir>/events.jsonl`, one compact JSON object per line. The run directory is the one the
producer writes `state.json` into: `.simplicio-loop/loop-runs/<run-id>/` for runs armed by
`simplicio-loop run`, `.simplicio-loop/orchestrator/runs/<run-id>/` for the orchestrator layout
(both roots are searched by the hooks and should be by readers).

| Property | Behaviour |
|---|---|
| Ordering | `seq` starts at 1 and grows by 1 per event of the run, allocated under the cross-process sidecar lock of `scripts/_locked_append.py` (`events.jsonl.lock`): no gaps, no duplicates, across processes and rotations. |
| Atomicity | One `write()` per batch under the lock; a reader never sees a partial line from a producer. A torn line left by a crash is skipped by readers and the next append starts on a new line. |
| Rotation | When an append would push `events.jsonl` past `SIMPLICIO_DASHBOARD_EVENTS_MAX_BYTES` (default 16 MiB) it is renamed to `events.jsonl.1` (older files shift to `.2` … up to `SIMPLICIO_DASHBOARD_EVENTS_KEEP`, default 3). Replay reads `.N` … `.1`, then `events.jsonl`. A tailing reader must reopen the file when its inode changes. |
| Durability | Lines are flushed to the OS on every append. `SIMPLICIO_DASHBOARD_EVENTS_FSYNC=1` also fsyncs each append (slower; see the benchmark). |
| Kill switch | `SIMPLICIO_DASHBOARD_EVENTS=0` (or `false`/`no`/`off`) writes nothing, not even the lock file. |
| Fail-open | Emitting never raises and never blocks the loop: a failure (unwritable sink, lock timeout after 1 s, invalid event) drops the event and records a diagnostic: one stderr line per reason and process, an in-process list (`dashboard_events.diagnostics()`), and one JSON line in `SIMPLICIO_DASHBOARD_EVENTS_DIAGNOSTICS` (default `<tmp>/simplicio-loop/dashboard-events-diagnostics.jsonl`, schema `simplicio.dashboard-event-diagnostic/v1`). |
| Privacy | Payload keys named like secrets (`token`, `password`, `api_key`, `authorization`, `cookie`, `credential`, `private_key`, `secret`) are replaced with `[REDACTED]`, secret-looking values (bearer tokens, GitHub/OpenAI/AWS keys, URL credentials) are masked, and a payload above 32 KiB is replaced by `{"truncated": true, "bytes": N}`. Hooks never record the prompt or the command text. |

## Envelope

Every field is always present (`null` where it does not apply); no other field is allowed.

| Field | Type | Meaning |
|---|---|---|
| `schema` | `"simplicio.dashboard-event/v1"` | envelope version |
| `event_id` | ULID (26 chars, Crockford base32) | unique id; sortable by time; deterministic for derived events |
| `seq` | integer ≥ 1 | monotonic per run, gap-free |
| `ts` | `YYYY-MM-DDTHH:MM:SS.mmmZ` | UTC emission time (derived events: the source record's time) |
| `run_id` | string | the run directory name |
| `task_id` | string or `null` | `null` for collection events |
| `scope` | `collection` · `task` · `scenario` | same policy as `simplicio.event-metadata/v1`: collection ⇒ `task_id: null`; task/scenario ⇒ `task_id` required |
| `source` | `hook` · `runner` · `worker` · `oracle` · `operator` | who produced it |
| `kind` | catalog name (below) or `<namespace>.<kind>` | what happened |
| `phase` | string or `null` | the run phase (`intake`, `awaiting_decision`, `mapping`, `planning`, `executing`, `validating`, `watching`, `delivering`, `done`, `partial`, `blocked`, `cancelled`) |
| `lane` | string or `null` | lane / worktree / branch, when known |
| `iteration` | integer ≥ 0 or `null` | loop iteration, when known |
| `severity` | `debug` · `info` · `warning` · `error` | for alerting |
| `payload` | object | kind-specific details (below) |
| `refs` | array of strings | receipts/files backing the event; relative to the run directory when inside it |
| `producer_version` | `<producer>@<version>` | e.g. `simplicio-loop@3.47.0` |
| `derived` | `true` (optional) | only on events rebuilt by the retroactive adapter |

### Namespaces

Bare kind names belong to the loop (coding) catalog below and must be in it. Another product reuses
the same envelope with its own namespace: `<namespace>.<kind>` (lowercase, e.g.
`marketing.post_published`). The `loop.` namespace is reserved. Validators accept any well-formed
namespaced kind; each namespace owns its own catalog.

"Reserved" kinds are part of the stable catalog; their producers land with the dashboard issues
that need them (#1404 agents and cost). Their payload fields above are the expected
shape, not yet emitted.

`token_usage` and `cost_sample` stay reserved until a producer exists (issue #1404). The reader exists: `dashboard/budget.py` sums them (`input_tokens`, `output_tokens`, optional `lane`, `model`; `usd`) for the budget panel and the budget alerts.

## Producers

- **Runner** (`simplicio_loop/runner.py`): `_record_event` keeps writing the progress event into
  `state.json` and maps it onto this stream with `specs_from_runner_event`; a transition goes through
  `events_from_transition`, the same function the retroactive adapter uses on `transitions.jsonl`, so
  the logic exists once. `technical_debt.record_notice` emits through the same seam.
- **Hooks** (`hooks/_dashboard_emit.py`): `loop_stop` (watcher gate, stall, iteration finished/started),
  `action_gate` (`gate_evaluated`, `gate: action`, on a BLOCK only; the command is not recorded) and
  `user_prompt_submit` (`iteration_started`, source `operator`). A hook finds its run through
  `SIMPLICIO_RUN_DIR`, then `SIMPLICIO_RUN_ID` (either run root), then the single non-terminal run
  updated in the last 24 hours. With no run, or several active runs, it emits nothing.
- **Workers and shell hosts**:
  `python3 scripts/dashboard_events.py emit RUN_DIR --kind lane_progress --source worker --payload '{"step": "lint"}'`.

### Quality producers

- **Quality events** (`simplicio_loop/quality_events.py`, called by `simplicio_loop/apply.py` after each
  task's `check` command): source `worker`, scope `task` with the task's `task_id`. `iteration` comes from
  the `SIMPLICIO_ITERATION` environment variable when it is set; otherwise it is `null` and the Live
  reducer attributes the event to the current iteration.
- **Parsers** read real tool output only: pytest, unittest, jest, vitest and go test; ruff, mypy and
  flake8; coverage.py, pytest-cov and jest coverage. Output that is not recognised emits nothing.
- **Diff**: each iteration's measured git diff goes in an `apply_result` event with payload `step: "diff"`.
  No new kind is added.

**UNVERIFIED:**

- Flaky tests: the events carry counts, not per-test ids, so the flaky rule cannot run.
- The matrix by unit, integration, system and regression level, and red to green transitions per test id.
- The diff virtualisation benchmark: no measured benchmark exists.
- The producer module and its tests are not in this tree yet, so the payloads above are the specified
  shape, not yet emitted.

## Reading

```python
from simplicio_loop.dashboard_events import read_events
events = read_events(run_dir, since_seq=0)  # ordered by seq; rotated files included
```

`python3 scripts/dashboard_events.py read RUN_DIR [--since N]` prints the same as JSONL and
`python3 scripts/dashboard_events.py validate FILE` checks a file.

### Older runs (retroactive adapter)

A run without live events (no `events.jsonl`, or one that holds only the older progress records) is
rebuilt from `transitions.jsonl` + the `state.json` progress events (or, when the run predates
those, its receipts: `task-contract.json`, `mapper-context.json`, `plan.json`,
`operator-receipt.json`, `evidence-receipt.json`, `delivery-receipt.json`,
`completion-receipt.json`). Rebuilt events carry `derived: true`, are ordered by their source
timestamp, numbered `seq` 1..N, and get deterministic `event_id`s, so re-reading the same run yields
the same ids. A run that was upgraded mid-flight shows only its live part.

## Overhead (measured)

`python3 scripts/dashboard_events.py bench` times 2,000 `emit` calls (lock, `seq` allocation, append)
after a warm-up. On the development box (Linux 6.12, overlay filesystem, 8 vCPU, Python 3.13), on
2026-10-02:

| Mode | p50 | p95 | p99 |
|---|---|---|---|
| default (flush) | 0.13 ms | 0.16 ms | 0.18 ms |
| `SIMPLICIO_DASHBOARD_EVENTS_FSYNC=1` | 0.25 ms | 0.75 ms | 4.0 ms |

`tests/test_dashboard_events_system.py` fails if the default-mode p95 reaches 1 ms (best of three
runs). Re-run the command on the target machine for its own number.

## Alert frames (#1406, slice 1406b)

The stream also carries named frames for run alerts. They are not dashboard events and are not written to `events.jsonl`, so they do not take a `seq`:

- `event: alert_snapshot` with `data: {"alerts": [...]}`: the alerts active when the connection opened. It is sent after the history, so a reconnect gets the alerts that are still active.
- `event: alert_raised` with `data:` one alert: `{"id", "rule", "severity", "heading", "why", "ref"}`.
- `event: alert_cleared` with `data: {"id": "<alert id>"}`.

A client that treats every `data:` line as an event must skip frames with an `event:` name, as `EventSource` does for named events.

## Coordination is not an event

`/api/coordination` reads the backlog JSONL, not `events.jsonl`, and writes no event kind. See [DASHBOARD.md](DASHBOARD.md#coordination-apicoordination).
