## Objective

Release simplicio-loop 3.51.0. The release runs setup during install. It requires an owner list for the 24/7 watcher. It removes the standalone binary. It changes macOS process and path handling.

This PR does not publish anything. The maintainer publishes after the merge.

## Implementation

**Install & setup**

- `simplicio-loop install` runs `setup` at the end, also without a terminal. A failed setup exits 2. A required evidence tool that is not ok exits 1 (#1841).
- `setup` detects a usable Python. A Microsoft Store alias does not count. If `setup` finds no usable Python, it installs Python 3.11 with winget on Windows when winget runs. Otherwise it uses `uv python install 3.11` (#1842).
- `setup` checks and installs the evidence tools: `@playwright/test` 1.64.1 with its Chromium. `setup` only checks Node.js 22 or later. `doctor` lists one row per tool (#1843).
- `setup --with-hyperframes` installs the optional hyperframes explainer. `pip install simplicio-loop` and `simplicio-loop install` register the Stop and PreToolUse hooks. `doctor` checks Python against `requires-python` (3.11).

**24/7 watcher**

- `SIMPLICIO_247_OWNERS` replaces the hardcoded `simpletibr` org and the `simplicio*` repo-name prefix filter. The watcher watches a repo when the repo's own `.simplicio-loop/loop.toml` enables it.
- The loop addresses a repo as `owner/repo` everywhere: claims, leases, status, worktrees, `gh` calls, PR URLs and run folders.

**Hosts**

- The release wires 20 hosts on the `.claude/skills/` plus `AGENTS.md` surface. Each has adapter code, a host test and the `wired` catalog status.
- The release wires eight more hosts: GitHub Copilot, OpenCode, Simplicio Agent (Hermes), Continue, Qwen Code, Gemini, Aider and OpenClaw.
- The catalog has 34 wired adapters and 0 listed hosts. DeepSeek is a model provider (status `provider`), not a host.
- `simplicio-loop install` writes an AGENTS.md marker block for every host with an entry file. `orca-dev` is opt-in by name.

**Evidence**

- `web_verify` and `video_evidence` run their specs on the Playwright that `setup` installs. A failed check reports Playwright's own `Error:` line.
- The 24/7 watcher records front-end changes with Playwright. hyperframes runs only when a work item asks for an explainer video.
- Evidence runs inside the 24/7 sandbox. Each run uses a fresh temp folder. The project pins hyperframes to 0.7.111 in its own npm project.
- `video_evidence` checks FFmpeg with `-version` before use. A failed mp4 conversion keeps the `.webm` and puts the FFmpeg error tail in the verdict.

**Mapper**

- `ask` writes its savings ledger to the query's state dir (`--out`, default `.simplicio-loop`), not to the mapped tree.
- `scan --sync` gives its worker an absolute `--wait-until`, set at spawn. Interpreter start-up counts against the scan budget.
- Store migration, registry and health count a lock owner under another user (EPERM) as live. Only ESRCH marks it dead.

**Dev CLI**

- The changeset transaction counts a lock owner under another user (EPERM) as live. Only ESRCH marks it dead.
- The JSON boundary checker classifies every file under a registry path that ends in `/`.

**Reliability & process**

- The loop's kill paths share one process-group helper, `simplicio_loop/proc_group.py`. A hung login check ends at its timeout, and the loop kills its whole process group. Measured with fake CLIs at a 2.0 s timeout, the count path went from 30.79 s to 2.02 s.
- On macOS, a child that exited and is not reaped counts as dead. `simplicio-loop dashboard` names the process that holds a taken port on macOS, using `lsof`.
- The liveness probe moves to `simplicio_mapper/process_liveness.py`. `simplicio-loop verify` on a repo with no runs reports `no_runs` instead of a traceback.
- Squads runs keep their state under `.simplicio-loop/squads-run/`, not in the `.simplicio/` folder.
- `scripts/version_sync.py apply` rewrites, and `check` reads, the `installed_version() or` fallback literal in `simplicio_loop/__init__.py`. Before, `apply` left it at the old version and `check` still reported READY. Tests: `tests/test_version_sync_unit.py`, `tests/test_release_manifest_unit.py` (9 new cases, red before the fix).

**Removed**

## Deployment and upgrade notes

**Upgrade notes**

- **24/7 watcher:**
  - Set `SIMPLICIO_247_OWNERS` to the GitHub owners to watch. An owner is an organization or a user. Separate the owners with commas.
  - The service refuses to start without this variable.
  - The claim, lease and status keys change from `repo#N` to `owner/repo#N`.
  - Before you upgrade a running service:
    1. Stop the service.
    2. Remove `baseline.json`, `claims.json` and `fixes.json` from the service state directory. See `docs/WATCHER_247.md`.
  - The service no longer uses old work folders named `<repo>` without an owner. You can remove them.
- **Standalone binary:**
  - This release removes the standalone binary. The binary was never published.
  - Install with `pip install simplicio-loop`. Update with `simplicio-loop update`.
  - For a git checkout, use `git pull` and `bash scripts/dev_install.sh`.

The maintainer runs these publish steps after the merge. No one runs them from this PR.
